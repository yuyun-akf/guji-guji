# 🍡 咕叽咕机 · GujiGuji

SillyTavern **1.18 / 1.19** 虚拟手机扩展，当前 **v0.8.0 测试版**。入口：酒馆魔法棒 →「咕叽咕机」。悬浮按钮可选、默认关闭。

安装与更新：https://github.com/yuyun-akf/guji-guji

## 更新到 0.8.0

在酒馆扩展管理器更新本扩展，完成后刷新页面。确认扩展版本和手机桌面显示 0.8.0；仍显示旧版时重新加载页面。不要卸载、清空浏览器数据或删除聊天来排查入口问题。

0.8.0 重做「我」个人主页：展示 user 头像/人设、上传自定义头像、分组收纳表情包和设置。朋友圈文本/图片发布统一移到「发现」。新增角色/NPC 自主私聊和自主朋友圈的固定周期或随机天数间隔设置，分别保存，**默认均关闭**。开启后在酒馆页面保持运行且可见时检查到期，每次只尝试一项活动；关闭页面不会在系统后台生成，也不会补发离线错过的所有消息，启用后会消耗模型 API。

主线仅明确交换联系方式但没有申请结果时，可在「我 → 角色自主活动」勾选「角色自主决定是否申请好友」。此项默认关闭，开启后会额外调用一次模型判断申请或跳过；同一段主线证据只检查一次，不会自动替 user 同意好友。

新增主线关系同步：明确的长期既有关系（例如从大一到大三一直是室友）可初始化为好友；主线明确记录某个具体联系人申请添加 user 时，「新的朋友」显示由对方发来的待处理申请，可直接同意或拒绝；互相扫码通过好友时可直接成为好友。模糊代词或仅交换电话号码不自动认定申请成功。关系识别可能漏判，可手动修改状态；「我」可暂停自动同步，适用于小手机时间线早于主线。不会覆盖旧版本已保存的好友状态、私聊或 NPC。


0.7.0 修复了朋友圈新增控件未登记造成的启动异常。现在先注册入口，再初始化手机；初始化失败清理半成品并允许重试。菜单延迟插入或被替换时自动补注册，不依赖 APP_READY 再次触发，不再在 15 秒后放弃。

bootstrap 统一管理启动、合并并发加载；禁用期间完成的加载不会复活界面；失败后重新启用可重试。主模块 URL 带版本号，减少更新后载入旧代码的情况。没有增加强制悬浮按钮。

## 当前功能

- **四栏导航**：消息、通讯录、发现、我。「新的朋友」只展示收到或发出的申请；通讯录只显示好友。添加页可以继续查看未添加人物。
- **统一添加入口**：通讯录 → 添加好友／故事人物，选择手动创建或扫描角色设定／世界书。扫描候选须逐个核对、勾选、确认，不直接变成好友。
- **人物扫描**：默认只读取当前角色卡、角色内嵌/绑定世界书、当前 user 人设及其绑定世界书。其他世界书须明确手选；不再扫描全部可用世界书，也不因手机预设选用了文风书就将它加入扫描。跳过禁用条目，排除当前 user 名称和人设里明确填写的别名，以及文风/写作规则条目。{{user}} 设定中的已命名朋友仍可识别。每本最多280条；规则扫描仍可能误判或漏判，请核对候选。旧版本已保存的人物不会被自动删除。
- **关系门槛**：新故事默认非好友。扫描人物须有正文交换联系方式线索或玩家手动确认，才能申请；手动创建人物允许主动申请。旧关系保留。当前可根据正文明确提及的发起人和申请事件产生收到的好友申请；模糊否定、代词和第三人叙述仍需人工核对。
- **图片表情包**：安装后库为空，不附带任何图片、不读取外部表情包仓库。在「我」上传 PNG/JPG/WebP/GIF，文件名作为名称，可点击改名或删除；聊天图片菜单可「收藏为表情包」。同一酒馆账号下跨角色/存档共用，user 点图发送，char 根据名称/关键词选择库中图片。图片表情包按文字标签参与模型上下文，不强制视觉 API；角色是否选择发送取决于模型。建议填写准确的内容/情绪关键词。每张350KB以内，最多80张、合计约3MB；删除库中图片不删除已发送的聊天图片。
- **聊天工具**：图片、引用及消息操作。电话、转账、定位填写剧情通话邀请、虚拟金额、故事地点，不是实际电话、支付或定位。普通照片识图仍需支持视觉的独立 API；表情包不受此限制。图片和表情包 JSON 备份保留载荷。
- **朋友圈**：「发现」发表当前玩家的文字或单张图片动态，保存于当前故事；「我」设置角色/NPC 定时或随机自主发朋友圈；暂无点赞评论、群聊。
- **独立私聊**：当前角色与每位 NPC 分开保存消息和关系，按当前角色的当前正文聊天存档隔离。
- **设置与主题**：酒馆当前连接或独立 OpenAI 兼容接口、预设/世界书条目选择、头像、壁纸、字体、图标、故事日历。独立 API 密钥仅在内存，刷新后重新填写。
- **备份与诊断**：聊天 JSON 导出/复制/导入、删除单条、清空会话、运行日志。导入替换当前联系人的手机消息，先保存备份。

## 旧聊天保护

存储键仍为 `chatMetadata.st_little_phone_v1`，数据版本仍为 1。升级、启动、启用/禁用不会清空聊天，不迁移存储键。旧消息、消息 ID、自定义字段及主角色/NPC 独立对话保持兼容；没有 friendship 字段的旧聊天保留好友状态，新故事才默认陌生人。

可在更新前导出重要手机对话和酒馆正文存档。删除 NPC、清空/删除聊天及导入替换是玩家主动操作，不属于升级过程。

## v0.8.0 验收要点

1. 更新并刷新，确认魔法棒入口与版本号 0.8.0；旧存档和旧 NPC 仍保留。
2. 在「我」查看头像和人设，可换头像。在「发现」发布文字+图片、纯图片或纯文字，检查动态是否保留。
3. 对新存档检验“长期室友”自动成为好友；主线出现“某个 NPC 向 {{user}} 发送好友申请”后，申请只应属于室友戊，玩家可同意/拒绝。已保存旧关系不应被覆盖。
4. 在「我」将私聊设为“固定 1 天”、朋友圈设为“3 天内随机一次”，保存后会显示预计下次时间。可以先使用较短间隔做测试（0.04 天约 58 分钟），默认不开启自主生成。
5. 关闭酒馆页面或安卓杀后台时不会运行；重新打开最多处理到期的一次活动。若生成失败，从运行日志查看错误；独立 API 密钥刷新后需要重新填写。

## Termux 优先验收

1. 更新刷新后确认 0.8.0，魔法棒只有一个「咕叽咕机」，能够打开。
2. 旧消息仍在，悬浮按钮默认关闭。在「我」上传表情包、设置自主活动，在「发现」发表带图动态；取消相册选择应仍在原对话。
3. 禁用再启用后入口恢复；切换正文存档不串数据。
4. 若仍缺入口，记录酒馆完整版本、浏览器/WebView 版本、插件版本，截图启动诊断。B-ERR 表示加载/初始化失败；B3 表示界面/菜单未就绪。无需发送密钥或私聊正文。

## 开发测试

无需依赖：

```sh
node --test tests/core.test.mjs tests/startup.test.mjs tests/social.test.mjs
node --check index.js
node --check bootstrap.js
```

可选真实浏览器 DOM 测试（模拟酒馆上下文，不等于完整酒馆集成）：

```sh
npm install --no-save playwright
npx playwright install chromium
node --test tests/browser.test.cjs
```

环境变量 `GUJI_BROWSER_PATH` 可指定 Chromium/Edge 可执行文件。
