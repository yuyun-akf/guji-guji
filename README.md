# 咕叽咕机 · GujiGuji

SillyTavern 第三方前端扩展，版本 **0.3.6（Android 界面显示修复测试版）**。GitHub 仓库：<https://github.com/yuyun-akf/guji-guji>。

这是用于验证手机桌面、核心聊天与存档的起步版本；代码已完成静态检查，但**尚未在你的 SillyDroid / Termux / SillyTavern 1.19.0 真机环境中验证**。请先备份需要测试的酒馆聊天存档。

**0.3.3 双入口：** 默认向酒馆 **魔法棒菜单新增「咕叽咕机」**，点击打开新版手机桌面。独立紫色 `☏` 作为可选悬浮按钮，在手机「设置 → 打开方式」手动开启，**默认关闭**。新版的两种入口调用同一界面、使用同一存档。

**0.3.4 可见性修复：** 点击「咕叽咕机」时重新确认主界面在 DOM 中、将面板挂到文档根节点并强制显示；等待魔法棒菜单收起后核对面板尺寸和顶部命中情况。如果没有真正显示，直接用可见的原生提示框报错。避免仅凭菜单项已注册就误判为手机可用。上一实例遗留的同名菜单项会重新绑定点击处理。

**0.3.5 入口隔离：** 已删除本扩展中针对其他插件「手机」入口的隐藏、恢复与自动干预代码。通过源文件和录屏确认，魔法棒中的「手机」来自另一个已安装的综合扩展 [Acsus-Paws-Puffs](https://github.com/Hmkovo/Acsus-Paws-Puffs/blob/main/toolkit/phone/index.js) 的内置模块，并非本仓库。两者独立安装、独立维护。彻底删除 Acsus 的手机源码需要处理对应插件，更新或卸载咕叽咕机不能实现。

**0.3.6 手机端显示修复：** SillyDroid 实机曾报「手机界面不可见或被遮挡（344×630，顶部命中：无）」：面板已创建但在 WebView 中没有得到有效屏幕命中。本版改用浏览器原生 `dialog.showModal()` 将手机主屏置于顶层，按视口中央定位；不再把手机根节点放在 `html` 元素下，也不再用移动端不可靠的 `elementFromPoint()` 判断是否成功。失败时报告面板和视口坐标。悬浮按钮依然默认关闭。

**启动诊断：** `bootstrap.js` 在首次运行时短暂显示「启动检查 0.3.6」，成功注册魔法棒入口后自动消失；如果入口失败，诊断浮层保留以便截图排查。

- `B1`：启动入口执行，正在读取主模块；`B2`：主模块载入；`B4`：魔法棒里的咕叽咕机入口已注册。
- `B3`：未找到魔法棒入口或手机界面；`B-ERR`：主模块读取或初始化出错，旁边会显示脱敏的错误摘要。
- **如果诊断浮层完全没有出现**，说明这份新版入口没有被当前页面执行，需要进一步查扩展脚本加载、实际安装的仓库/版本或缓存。
- 可以点击浮层右上角 `×` 关闭。请截图它当前显示的代码，**不用提供 SillyDroid 的服务器运行日志**。

这是定位启动问题的测试版本，不能仅凭 GitHub 更新成功就宣称在手机上验收成功。现在请优先测试魔法棒里的**「咕叽咕机」**（并非旧的「手机」）；带「动态／联系人／消息」的 QQ 风格界面属于另一套 UI。

## 本版可做什么

- 点击酒馆魔法棒菜单里的「咕叽咕机」**先进入手机桌面**；如果在设置中开启悬浮按钮，也可以从 `☏` 打开。当前有「咕叽聊」「运行日志」「设置」三个 App；相册、购物、外卖显示「待开发」，尚没有真实业务功能或第三方账号连接。
- 悬浮按钮开关保存在酒馆的 `extensionSettings.gujiguji.floatingLauncher` 中，默认关闭；不会改变其他插件设置。
- 在「咕叽聊」里显示独立的消息气泡，只有一个「发送并生成」按钮（也可在输入框按 Enter）。一次点击会先保存玩家消息，再通过酒馆 API 生成角色回复；失败后可单独点「重新生成上一条回复」，不会复制玩家消息。
- 默认使用当前单人聊天里的角色设定；群聊暂不支持。
- 为当前角色的当前**聊天存档**保存独立手机消息。切换聊天存档时显示对应的手机记录。
- 在「设置」中可修改虚构手机故事时间；每条消息记录发送时的故事时间。
- 通过当前酒馆所连接的生成 API 发起独立生成，不把小手机消息插入正文 `chat` 数组。
- 生成期间显示「对方正在输入…」与已等待秒数；120 秒没有得到结果时提示超时，支持对未回复的最后一条消息重试，不重复添加 user 消息（超时不能保证底层 API 请求已被取消）。
- 手机桌面的「运行日志」App 会记录本次页面的消息保存、开始生成、生成成功、好友处理与捕获的错误，附带时间、可用错误状态码和脱敏信息；聊天页也有明显的「查看运行日志」入口。最多保留最近 24 条记录，可复制或手动清空。
- 好友状态支持已是好友、陌生人、收到申请、申请待处理和已拉黑；可以删除、拉黑、解黑、重新申请、撤回、同意和拒绝。
- 重新发起的好友申请交由当前角色模型决定同意或拒绝。模型或 API 出错时申请保留为待处理，可点「重试申请」。
- 在「按已有剧情设定好友状态」中，可以按当前故事的既往设定手动选择初始好友关系。
- 角色切换中已经发出的异步回复不会追加到切换后的存档。

## 还没有实现

- 角色定时或自主主动给用户发消息（下一阶段优先）。
- 进入后台后推送 Android 系统通知。
- 手机相册、发送真实图片、视觉识图。
- 正文与手机双向提取、检索、引用历史事件；当前手机聊天**不会自动进入正文提示词**，正文模型不会自动记得手机发生过的事。
- 自定义多个联系人、群聊、语音、朋友圈，以及购物、外卖、相册等桌面 App 的实际业务功能。
- 独立手机模型配置：暂时沿用当前 SillyTavern 的 API 与生成设置。
- 角色主动发起的好友申请和自动联系人列表：目前需要按既有剧情手动设成「对方向我申请」，后续接入角色主动消息机制。

## 安装

### 通过 GitHub 仓库安装或更新（推荐）

在酒馆的 `扩展 → 安装扩展 / Install Extension` 中输入仓库地址 `https://github.com/yuyun-akf/guji-guji`。仓库根目录直接包含 `manifest.json`、`bootstrap.js`、`index.js` 和 `style.css`，这是官方支持的第三方扩展安装方式。

如果此前安装了旧版，请从酒馆的扩展管理器更新此仓库的扩展，再刷新页面。不要同时安装两个不同文件夹的副本。

**注意：本地 ZIP 不是 Git 仓库地址，不能把 ZIP 文件名直接粘贴到安装网址栏。**

### 手动本地安装

1. 将本插件源文件放在一个独立文件夹中，例如 `guji-guji/`，文件夹内直接有 `manifest.json`、`bootstrap.js`、`index.js`、`style.css`。
2. 将文件夹复制到目标 SillyTavern 的扩展目录，如 `data/<user-handle>/extensions/guji-guji/`。实际用户目录取决于酒馆部署方式。
3. 重启或刷新 SillyTavern，启用扩展；进入一张单人角色卡的聊天存档。
4. 点击酒馆魔法棒 → 「咕叽咕机」打开手机桌面，再点「咕叽聊」。

Android **SillyDroid 和 Termux 的文件位置与访问方式可能不同**。如果无法访问扩展目录，先不要改动系统文件，改走 GitHub 仓库安装更合适。

## 第一次测试清单

1. 打开普通单人角色卡，点击魔法棒，应有独立的「咕叽咕机」选项；点击后**先看到手机桌面**，有「咕叽聊」「运行日志」「设置」。默认不显示悬浮按钮。
2. 进入「设置」开启悬浮按钮，应多出紫色 `☏`；关闭开关后它消失，魔法棒入口仍可使用。两个入口显示相同的手机聊天存档。
3. 进入「设置」修改小手机故事时间，例如 `2021-09-01 20:00`，关闭后再打开时间不丢。
4. 进入「咕叽聊」，只点一次「发送并生成」，先保存 `晚上好` 再自动生成一条角色回复；正文聊天窗口没有多出任何楼层。
5. 刷新页面后，原手机消息仍在。
6. 切换到另一张角色卡，再切回：两边手机聊天互不混淆。
7. 切换到同角色的另一个聊天存档：手机记录也应分开。
8. API 不可用时出现提示，原文与其他插件没有被修改。
9. 发送消息后能看到「对方正在输入…」和等待秒数；首页「运行日志」会显示开始生成与成功记录。回复失败时聊天页的「查看运行日志」按钮突出错误数量，打开后能查错并重试。
10. 「删除好友」后历史消息仍在，但暂时不能发送；重新申请后模型可决定接受或拒绝。
11. 「拉黑」后不能发送，解除拉黑后可以重新添加。设置「对方向我申请」后可测试「同意申请／拒绝」。

如果步骤 2–6 中任何一项失败，请保留报错截图和最短复现步骤，我们可以专门修改兼容层。

## 存档结构与边界

- 命名空间：`chatMetadata.st_little_phone_v1`。
- 为兼容原存档，数据版本号与命名空间保持 v1；旧存档缺少好友状态时默认已是好友，不会清空记录。
- 好友状态按**当前角色的当前聊天存档**保存，不跨不同平行存档；关系变化不会删除历史消息。
- 本版不会读取或修改角色主聊天文本，也不会给角色偷偷注入额外正文记忆。
- 消息文本按纯文本显示（`textContent`），不会解释为 HTML。
- 手机历史目前在小手机生成时仅取最后 **24** 条作为上下文；完整消息仍在当前存档的手机记录中。长对话之后需要加入摘要/检索机制。
- 代码不包含 API Key，也不会请求独立第三方服务器；实际模型请求由 SillyTavern 当前生成接口处理。
- 「运行日志」显示本插件记录的操作状态和能捕获的客户端/API 调用错误，**不提供全部 SillyDroid/Node 服务端日志**。日志只保留在当前页面内存中（最多 24 条），且不包含聊天正文、原始请求体或 API 密钥。

## 兼容目标

- SillyTavern **1.19.0**。
- SillyDroid WebView / Termux 中的 SillyTavern 页面。
- 当前酒馆已配置的 OpenAI 兼容接口。

这些是**目标环境**，不是已经全部通过实机测试的认证；优先在用户的 SillyDroid 上验收，再逐步放开后续功能。

## 后续路线

1. **下一阶段**：小手机打开且酒馆前台运行时，角色可以按条件主动发消息及主动申请好友；增加开关、频率上限、防重复和防刷 API 请求。
2. **后续阶段**：手机事件提炼与正文可控的双向记忆同步，尊重玩家编辑的时间线、不跨越尚未发生的故事日期。
3. **后续阶段**：相册、真实图片发送、视觉模型识别；不支持视觉时提供手动描述并清楚标示来源。
4. **逐个扩展桌面 App**：购物、外卖等按照独立功能模块开发；目前不接入真正淘宝/美团账号或支付功能。
5. 运行稳定后，再评估后台 Android 通知能力与 SillyDroid 适配。
