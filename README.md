# 🍡 咕叽咕机 · GujiGuji

SillyTavern **1.18 / 1.19** 虚拟手机扩展，当前 **v0.8.10 测试版**。入口：酒馆魔法棒或扩展设置 →「咕叽咕机」。悬浮按钮可选、默认关闭。

安装与更新：https://github.com/yuyun-akf/guji-guji

## 更新到 0.8.10

在酒馆扩展管理器更新本扩展，完成后刷新页面。确认扩展版本和手机桌面显示 0.8.10；仍显示旧版时重新加载页面。不要卸载、清空浏览器数据或删除聊天来排查入口问题。

0.8.10：**悬浮按钮诊断版。** 此前“悬浮按钮已开启”只说明扩展设置里的开关为真，不能证明图标真的显示。这次在用户切换悬浮开关、关闭小手机后及按钮意外消失时，检查 DOM 是否存在、CSS 是否隐藏、尺寸和位置是否有效、按钮中心是否被其他元素挡住。结果写进现有小手机「运行日志」，扩展设置的状态文字也会更新；无须禁用其他插件来猜测，更不会额外调用模型。若依然不可见，请先通过魔法棒／扩展设置打开手机，再关闭手机，随后重新打开「运行日志」，复制最新的「悬浮按钮诊断」记录。**这是定位问题的版本，不声称已修复所有安卓显示情况。**

0.8.9：**扩展设置页使用酒馆原生的折叠标题、主题箭头、按钮和复选框**，跟随正在使用的酒馆美化；不再使用浏览器默认 `details` 样式。旧版本的同名折叠框热更新时可自动替换。悬浮按钮改为小手机图标而不是电话符号，配色引用酒馆主题变量；位置、显示、层级在 JavaScript 中另行强化，以降低安卓旧 CSS 缓存和其他主题覆盖的风险。开关状态会直接显示在扩展设置内，按钮意外脱离页面时可尝试重新挂载。仍默认关闭，且只在酒馆网页内部悬浮，不是安卓系统级浮窗。**必须在真实安卓客户端复测显示效果。**

0.8.8：**表情包气泡只显示图片，不把 `[表情包：…]` 名称／说明印在聊天里**。用户点选表情包时先按 user 身份保存；模型也会被明确提醒，不能把 user 的图当成自己发的。保留文字标签用于模型理解图片含义。此处已做自动化模拟测试，真机具体收发顺序仍需核验。

在「我 → 表情包库」现可导入 ZIP 整包、JSON，或一次选择图片与 CSV 目录。支持 `表情包目录.csv` 中的「内容」「用途」「相对路径／原文件名」自动匹配；保留图片原始内容，不必逐张改备注。常见 ZIP 的压缩存储方式可直接读取；部分旧安卓内核不支持压缩 ZIP 时，请先解压，再选图片和 CSV。一次批量读取只保存一次扩展设置，表情包面板每次显示最多 24 张，可点“显示更多”。**仍有最多 100 张、总 Base64 图片数据约 3MB、单图 350KB 的安全上限**：超限会跳过，不能保证 100 张大图全部装入。旧表情包／已发图片不删除。

修正悬浮按钮的样式定位与显隐逻辑；新增酒馆「扩展设置」列表里的「📱 咕叽咕机」折叠项，内含打开手机与显示页面内悬浮按钮的开关。悬浮只在酒馆网页内显示，不是安卓系统级跨应用浮窗。

0.8.7：**手机预设是独立配置，不应随酒馆预设跳转。** 在手机设置中选择 A，退出再进入仍显示 A；选择 B 也同理。手机预设只是供玩家查看与勾选具体条目；已勾选的条目由手机单独读取，不要求当前酒馆使用同名预设，也不修改原酒馆预设。

朋友圈合并付费请求：开启「我 → 角色自主活动 → 新朋友圈自动生成最多四位角色的互动」后，user 发布一条动态时，一次请求生成符合联系方式条件的角色点赞／评论；角色自己发动态时，其发帖和其他角色互动合并在原本那一次请求里。你点赞、转发免费；你发表评论后需要角色回应时，评论会短暂排队，同一条动态的待处理评论合并为额外一次请求。**默认关闭**；关闭时也可以在动态上手动点「生成角色互动（1次请求）」。模型可能决定无人互动，返回格式错误时不会额外重试；一次请求仍按实际输入输出 token 计费，不等于零成本。注意同一轮批量生成属于模拟多名角色行为，实际人物口吻与互动真实性须在真实模型上测试。

0.8.6：删除重复的桌面朋友圈入口，朋友圈仍统一放在「咕叽聊 → 发现」，动态红点、点赞评论与互动功能保留。桌面原位置改为「吱付宝」，目前只是可以打开的应用页面，具体支付功能之后再设计。主页角色名称、添加人物示例、申请确认通过当前角色及 user 面具自动替换占位符。设置页预设选择器重新打开时显示**酒馆此刻激活的预设**，不从以前留在手机里的 B 预设恢复；旧勾选记录保留，其他预设条目不会混入本次生成。插件本身不修改酒馆全局预设；若重新载入后酒馆顶部的预设也跳回旧值，需要进一步排查宿主环境。


0.8.5：主页移除「× 位联系人」，新增朋友圈快捷入口。角色自主发布新动态会出现页面内提醒、首页未读数量及「发现」红点；打开「发现」清除未读。朋友圈补齐玩家点赞/取消赞、评论、回复评论和转发至自己的朋友圈。每条动态还可选择一名允许查看它的角色，点击「让角色互动」付费调用一次当前模型，由角色自行选择点赞、评论、回复或跳过。

**角色之间的联系必须单独确认**：在「通讯录 → 人物资料 → 角色之间的联系方式」勾选双方明确互加过的联系人；两人都与你是好友不等于彼此认识，默认没有任何角色间连线。没有互相联系方式的角色不能查看、点赞、评论或被提示看到对方的朋友圈，也不能读到对方在共同好友动态下的评论。角色好友状态变化后，已有连线会在非好友期间失效。手动测试互动不需要开启自动互动；如需对**新动态**自动尝试一次互动，可到「我 → 角色自主活动」勾选该选项并保存，默认关闭，可能额外消耗模型 API。旧动态及私聊不被迁移或清空。

0.8.4：角色头像上传复用「我」页面的照片压缩逻辑，支持常见手机大图（原文件上限 12MB）；350KB 限制仍仅适用于**表情包**。主动私聊到达时新增手机内弹窗、未读红点和计数，点击提醒可打开对应联系人；引用栏新增「取消引用」。新发消息按故事时间逐条递增分钟（允许日历手动跳时段），并明确提示模型不要在傍晚当作深夜。角色卡若设定网友身份尚未公开，手机生成将重点遵守真实身份与职业保密，禁止通过导演、剧本等话题旁敲侧击泄露。设置页现在可**先勾选多本世界书，再进入按书分组的条目页分别开启/关闭**；取消勾选某本书将暂停注入但保留它的条目选择。`{{user}}`、`{{char}}` 在手机显示和模型提示中按当前面具、当前联系人动态替换。 「我」的关系重查与活动设置保存有明确完成、未变化或错误提示。以上更改不自动修改旧聊天内容和时间戳；身份约束仍需在实际模型上检验。

0.8.3：修复聊天列表渲染异常、部分关系同步保存失败和旧版发出申请列表缺失。现在角色生成读取当前 user 人设、角色性格与示例对话，同时提示模型不要把人设里的私密信息等同于角色知情。世界书可在多本书中分别选择条目：选中条目仅参与匹配，常驻项直接生效，关键词、二级关键词与禁用项按独立手机上下文触发，最多约 12,000 字符；不再每轮无条件注入全部选中内容。暂未完整复刻酒馆世界书的递归激活、所有位置/分组与动态过滤器。

在「设置 → 正文记忆与互通」可读取已经安装的嘎嘎小狗记忆专用注入、柏宝书公开只读接口、留痕记忆已知文本字段（若这些来源在当前酒馆上下文可用），不安装或改写任何第三方记忆插件；**自动识别按顺序使用首个可用来源**。留痕记忆的其他存储结构、黑科技等未核实接口暂不读取，避免误把其他提示词当作剧情记忆。勾选「小手机时间早于主线」会完全屏蔽正文记忆。手机消息是否向正文注入可独立控制，默认关闭；只写入可清除的酒馆扩展提示槽，不改动正文原消息。实际匹配结果与粗略 token 估计记录于手机桌面的独立「运行日志」App，咕叽聊内不再另设日志按钮。

0.8.2：修复「我」的头像显示和上传：加载失败不再呈现空白方块，会显示备用头像；常见手机大照片上传时自动生成压缩缩略图，显示明确保存成功/失败原因。修正好友申请方向：新建申请默认由对方发来，进入「通讯录 → 新的朋友」显示红点和待处理数量，由 user 主动同意或拒绝；不再通过「我申请，对方审核」的旧流程。旧版已保存的 outgoing 状态不自动删除，可从联系人资料里改为「对方申请」。新增「我 → 角色自主活动 → 立即测试主动私聊」，主动调用一次模型且不重置已保存的时间计划。固定 1 天意味着保存起约 24 小时后到期，需要酒馆页面运行可见。触发后角色可以决定 SKIP，结果可在运行日志查看。

0.8.1：移除公共插件界面、示例和文档中写死的私人角色名，NPC 关系输入框统一使用 `{{char}}` 和 `{{user}}`，不修改任何已保存聊天、角色或关系数据。

0.8.0 重做「我」个人主页：展示 user 头像/人设、上传自定义头像、分组收纳表情包和设置。朋友圈文本/图片发布统一移到「发现」。新增角色/NPC 自主私聊和自主朋友圈的固定周期或随机天数间隔设置，分别保存，**默认均关闭**。开启后在酒馆页面保持运行且可见时检查到期，每次只尝试一项活动；关闭页面不会在系统后台生成，也不会补发离线错过的所有消息，启用后会消耗模型 API。

主线仅明确交换联系方式但没有申请结果时，可在「我 → 角色自主活动」勾选「角色自主决定是否申请好友」。此项默认关闭，开启后会额外调用一次模型判断申请或跳过；同一段主线证据只检查一次，不会自动替 user 同意好友。

新增主线关系同步：明确的长期既有关系（例如从大一到大三一直是室友）可初始化为好友；主线明确记录某个具体联系人申请添加 user 时，「新的朋友」显示由对方发来的待处理申请，可直接同意或拒绝；互相扫码通过好友时可直接成为好友。模糊代词或仅交换电话号码不自动认定申请成功。关系识别可能漏判，可手动修改状态；「我」可暂停自动同步，适用于小手机时间线早于主线。不会覆盖旧版本已保存的好友状态、私聊或 NPC。


0.7.0 修复了朋友圈新增控件未登记造成的启动异常。现在先注册入口，再初始化手机；初始化失败清理半成品并允许重试。菜单延迟插入或被替换时自动补注册，不依赖 APP_READY 再次触发，不再在 15 秒后放弃。

bootstrap 统一管理启动、合并并发加载；禁用期间完成的加载不会复活界面；失败后重新启用可重试。主模块 URL 带版本号，减少更新后载入旧代码的情况。没有增加强制悬浮按钮。

## 当前功能

- **四栏导航**：消息、通讯录、发现、我。「新的朋友」只展示收到或发出的申请；通讯录只显示好友。添加页可以继续查看未添加人物。
- **统一添加入口**：通讯录 → 添加好友／故事人物，选择手动创建或扫描角色设定／世界书。扫描候选须逐个核对、勾选、确认，不直接变成好友。
- **人物扫描**：默认只读取当前角色卡、角色内嵌/绑定世界书、当前 user 人设及其绑定世界书。其他世界书须明确手选；不再扫描全部可用世界书，也不因手机预设选用了文风书就将它加入扫描。跳过禁用条目，排除当前 user 名称和人设里明确填写的别名，以及文风/写作规则条目。{{user}} 设定中的已命名朋友仍可识别。每本最多280条；规则扫描仍可能误判或漏判，请核对候选。旧版本已保存的人物不会被自动删除。
- **关系门槛**：新故事默认非好友。扫描人物须有正文交换联系方式线索或玩家手动确认，才能申请；手动创建人物允许主动申请。旧关系保留。当前可根据正文明确提及的发起人和申请事件产生收到的好友申请；模糊否定、代词和第三人叙述仍需人工核对。
- **图片表情包**：安装后库为空，不附带任何图片、不自动读取外部仓库。可在「我」上传 PNG/JPG/WebP/GIF，或批量导入 ZIP／JSON／图片＋CSV；`表情包目录.csv` 的「内容」「用途」自动成为标签，名称也可手动修改。聊天图片可「收藏为表情包」。同一酒馆账号下跨角色/存档共用，user 点图发送，char 根据标签选择库中图片；表情包不强制视觉 API。每张350KB以内，最多100张、图片总数据约3MB；已发送的表情包不会因删除图库条目而丢失。
- **聊天工具**：图片、引用及消息操作。电话、转账、定位填写剧情通话邀请、虚拟金额、故事地点，不是实际电话、支付或定位。普通照片识图仍需支持视觉的独立 API；表情包不受此限制。图片和表情包 JSON 备份保留载荷。
- **朋友圈**：「发现」发表当前玩家的文字或单张图片动态，保存于当前故事；点赞、评论、回复与转发本身不调用模型。若开启默认关闭的自动互动，同条新动态的最多四名有权观看的角色合并为一次模型请求；你后续发表评论需要角色回复时，额外按批次调用一次。角色/NPC 自主发帖与其初始互动合并请求。角色之间互动必须明确互有联系方式；没有群聊。
- **独立私聊**：当前角色与每位 NPC 分开保存消息和关系，按当前角色的当前正文聊天存档隔离。
- **设置与主题**：酒馆当前连接或独立 OpenAI 兼容接口、多世界书按需激活、只读正文记忆、可关闭的手机记录影响正文、头像、壁纸、字体、图标、故事日历。独立 API 密钥仅在内存，刷新后重新填写。
- **备份与诊断**：聊天 JSON 导出/复制/导入、删除单条、清空会话、运行日志。导入替换当前联系人的手机消息，先保存备份。

## 旧聊天保护

存储键仍为 `chatMetadata.st_little_phone_v1`，数据版本仍为 1。升级、启动、启用/禁用不会清空聊天，不迁移存储键。旧消息、消息 ID、自定义字段及主角色/NPC 独立对话保持兼容；没有 friendship 字段的旧聊天保留好友状态，新故事才默认陌生人。

可在更新前导出重要手机对话和酒馆正文存档。删除 NPC、清空/删除聊天及导入替换是玩家主动操作，不属于升级过程。

## v0.8.10 验收要点

1. 更新并刷新，确认魔法棒入口与版本号 0.8.10；旧存档和旧 NPC 仍保留。
2. 在「我」查看头像和人设，可换头像。在「发现」发布文字+图片、纯图片或纯文字，检查动态是否保留。
3. 对新存档检验“长期室友”自动成为好友；主线出现“某个 NPC 向 {{user}} 发送好友申请”后，申请只应属于室友戊，玩家可同意/拒绝。已保存旧关系不应被覆盖。
4. 在「我」将私聊设为“固定 1 天”、朋友圈设为“3 天内随机一次”，保存后会显示预计下次时间。可以先使用较短间隔做测试（0.04 天约 58 分钟），默认不开启自主生成。
5. 关闭酒馆页面或安卓杀后台时不会运行；重新打开最多处理到期的一次活动。若生成失败，从运行日志查看错误；独立 API 密钥刷新后需要重新填写。
6. 设置页先勾选两本世界书，打开条目管理分别勾选；只提及第一本关键词，第二本不应进入注入预览。取消某本书后它的勾选记录仍在，但暂停注入。记忆插件存在时在日志查看识别来源；勾选过去时间线后应显示记忆已屏蔽。
7. 开启「手机聊天记录注入正文」后检查正文提示，关闭后应移除；切换不同正文聊天存档应完全隔离。此操作不会修改正文消息列表。
8. 上传一张超过 350KB、但不超过 12MB 的角色头像；主动私聊到达时确认弹窗与未读红点；引用消息后点「取消引用」。
9. 在 2026 年 1 月等隐藏职业身份的网友阶段测试聊天话题，在日历中从傍晚切换到夜间检查新消息时间；测试 `{{user}}`/`{{char}}` 展示与「我」中两项按钮的提示。
10. 首页不再显示联系人总数，也不再有「朋友圈」重复入口；取而代之的「吱付宝」可打开独立占位页。新朋友圈发布后「发现」仍出现未读提示，点通知直接进入朋友圈。
11. 点赞、取消赞、评论、回复及转发后刷新仍保留；联系人资料里只勾选主角 A 与网友 C 互相有联系方式，室友 B 不应出现在 C 的动态互动候选，也不能看到 B 留给你的评论。
12. 自动朋友圈互动默认关闭；开启后发布动态可在一次模型请求里让最多四位有权观看的角色自然互动，B 与 C 没有联系方式时不应互相回复。手动点「生成角色互动（1次请求）」应显示付费确认，不再要求每名角色单独请求。角色自主发布动态时，初始互动也应包含在发帖那一次请求里。
13. 在手机中独立选预设 A，离开设置重新进入仍显示 A，即使酒馆当前是 B；B 的勾选条目不丢失，用户勾选过的具体条目应按手机配置注入。切换角色和 user 面具后，可见名字应动态替换。
14. 连续给同一条动态评论两次，只应在短暂合并等待后触发一次角色回复生成；只点赞或转发不应调用模型。关闭自动互动后不应偷偷请求角色回应。
15. 在「我」将原表情包库 ZIP（带 `表情包目录.csv`）导入，确认名称和用途自动匹配，表情包图片未改动、不会重复写入；再次导入相同 ZIP 应提示跳过重复，打开图库一次最多载入 24 张。用 user 发送表情包，气泡应在右侧且只显示图片；角色若另外回图，应单独显示在左侧。
16. 到酒馆扩展设置检查是否出现单个「咕叽咕机」折叠项，点“打开咕叽咕机”能开启；开启页面内悬浮按钮、关闭手机后应在页面右下角看见按钮，关闭开关后按钮消失。禁用并重新启用扩展不应出现重复入口。
17. 扩展页「咕叽咕机」应与其他扩展一样使用酒馆主题的标题条、右侧圆形展开箭头；切换酒馆美化时应随主题变色。展开后勾选悬浮开关，查看其下面的即时状态文字；关闭扩展抽屉和小手机后应在右下角出现小手机图标。若仍不可见，请记录开关下方的文字与运行日志，不需要发送 API 密钥。
18. 在悬浮开关已开启但图标仍不可见时，用魔法棒打开小手机并正常关闭，然后通过扩展设置再次进入手机桌面「运行日志」，查看最新的「悬浮按钮诊断」分类：DOM 缺失、样式隐藏、屏幕外、被其他元素占用或几何位置正常。仅复制这条诊断，不要复制密钥和正文聊天。

无需依赖：

```sh
node --test tests/core.test.mjs tests/startup.test.mjs tests/social.test.mjs
```

可选真实浏览器 DOM 测试（模拟酒馆上下文，不等于完整酒馆集成）：

```sh
npm install --no-save playwright
```
