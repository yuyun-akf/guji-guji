# 🍡 咕叽咕机 · GujiGuji

SillyTavern **1.18 / 1.19** 虚拟手机扩展，当前 **v0.7.0 测试版**。入口：酒馆魔法棒 →「咕叽咕机」。悬浮按钮可选、默认关闭。

安装与更新：https://github.com/yuyun-akf/guji-guji

## 更新到 0.7.0

在酒馆扩展管理器更新本扩展，完成后刷新页面。确认扩展版本和手机桌面显示 0.7.0；仍显示旧版时重新加载页面。不要卸载、清空浏览器数据或删除聊天来排查入口问题。

本版修复朋友圈新增控件未登记造成的启动异常：手机初始化报错，原来位于其后的魔法棒注册无法执行。现在先注册入口，再初始化手机；初始化失败清理半成品并允许重试。菜单延迟插入或被替换时自动补注册，不依赖 APP_READY 再次触发，不再在 15 秒后放弃。

bootstrap 统一管理启动、合并并发加载；禁用期间完成的加载不会复活界面；失败后重新启用可重试。主模块 URL 带版本号，减少更新后载入旧代码的情况。没有增加强制悬浮按钮。

## 当前功能

- **四栏导航**：消息、通讯录、发现、我。「新的朋友」展示待处理申请；故事人物与好友分开展示。
- **统一添加入口**：通讯录 → 添加好友／故事人物，选择手动创建或扫描角色设定／世界书。扫描候选须逐个核对、勾选、确认，不直接变成好友。
- **人物扫描**：当前角色卡、内嵌/绑定世界书、手机选中的世界书及额外选择的世界书。额外世界书扫描可包含 user 设定中的朋友（如宝儿），最多 60 本、每本 280 条。本地规则扫描，不调用 AI，不修改正文世界书开关。过滤“与同学”等残缺词组，但仍可能误判或漏判。
- **关系门槛**：新故事默认非好友。扫描人物须有正文交换联系方式线索或玩家手动确认，才能申请；手动创建人物允许主动申请。旧关系保留。当前是规则识别与申请权限控制，**不会因正文出现线索就自动生成收到的好友申请**；复杂否定、代词和第三人叙述需人工核对。
- **聊天工具**：表情、图片、引用及消息操作。电话、转账、定位填写剧情通话邀请、虚拟金额、故事地点，不是实际电话、支付或定位。图片 JSON 备份保留载荷，模型识图取决于模型与 API。
- **朋友圈**：发现页发表当前玩家的文本动态，保存于当前故事；暂无 NPC 自动发帖、点赞评论。
- **独立私聊**：当前角色与每位 NPC 分开保存消息和关系，按当前角色的当前正文聊天存档隔离。
- **设置与主题**：酒馆当前连接或独立 OpenAI 兼容接口、预设/世界书条目选择、头像、壁纸、字体、图标、故事日历。独立 API 密钥仅在内存，刷新后重新填写。
- **备份与诊断**：聊天 JSON 导出/复制/导入、删除单条、清空会话、运行日志。导入替换当前联系人的手机消息，先保存备份。

## 旧聊天保护

存储键仍为 `chatMetadata.st_little_phone_v1`，数据版本仍为 1。升级、启动、启用/禁用不会清空聊天，不迁移存储键。旧消息、消息 ID、自定义字段及主角色/NPC 独立对话保持兼容；没有 friendship 字段的旧聊天保留好友状态，新故事才默认陌生人。

可在更新前导出重要手机对话和酒馆正文存档。删除 NPC、清空/删除聊天及导入替换是玩家主动操作，不属于升级过程。

## Termux 优先验收

1. 更新刷新后确认 0.7.0，魔法棒只有一个「咕叽咕机」，能够打开。
2. 旧消息仍在，悬浮按钮默认关闭；四栏、朋友圈文本、表情和更多工具可用。
3. 禁用再启用后入口恢复；切换正文存档不串数据。
4. 若仍缺入口，记录酒馆完整版本、浏览器/WebView 版本、插件版本，截图启动诊断。B-ERR 表示加载/初始化失败；B3 表示界面/菜单未就绪。无需发送密钥或私聊正文。

## 开发测试

无需依赖：

```sh
node --test tests/core.test.mjs tests/startup.test.mjs
node --check index.js
node --check bootstrap.js
```

可选真实浏览器 DOM 测试（模拟酒馆上下文，不等于完整酒馆集成）：

```sh
npm install --no-save playwright
npx playwright install chromium
node --test tests/browser.test.cjs
```

环境变量 `GUJI_BROWSER_PATH` 可指定 Chromium/Edge 可执行文件。
