# 吱付宝与正文事件同步（v0.9.0）

## 使用方法

### 账户余额和账单
打开桌面「吱付宝」。展开「调整余额」，输入希望设定的金额后点击「保存」。账户余额不得低于 0。余额变化会写入账单；账单包含发送/收取转账、红包、退款和账户调整。

### 私聊转账与红包
进入某位好友的聊天，点「＋」→「转账」或「红包」，输入金额与可选备注，点击「确认发送」。账户立即预留这笔资金并出现卡片。对方接受时状态变为「已收款」，拒收、撤回或故事时间超过 24 小时未领取时退款。当前版本可主动撤回自己的待处理款项；已处理的交易不可重复处理。

收到角色的转账/红包，会出现「收款／拒收」按钮。**只有你明确收款才增加余额**。不自动替 user 点击。

角色可根据自主判断在手机回复中发送红包/转账，也可选择收下或拒收你的转账。模型不作出有效的结构化交易决定时，交易继续待处理，不凭一句暧昧对话自动改变余额。

### 正文与小手机
在设置中勾选「正文与小手机同步已确认事件」，默认启用。正文中的角色明确说「我给你转了200元」「我已经给你转了两百块」等完成动作时，插件建立一笔待收款并发出手机通知。角色的假设、计划、委婉表达不会直接建立交易；仅简单、确定的中文表达可稳定识别，复杂句式可能需要在手机中手动补录。

在手机收款或拒收后，正文会通过扩展提示槽收到相关的已确认事件；不向正文泄露 user 的私有余额。手机处于过去时间线模式时暂停该联动，以免未来信息穿越到过去。

切换正文回复、编辑或删除已触发的转账消息时，插件重新比对来源：
- 未完成交易自动失效；
- 已收款且当前余额足够时入账冲正；
- 已收款但当前余额不足冲正时，标记「待核对」，不允许余额为负；
- 切回此前回复可重新建立新的待确认交易，历史冲正账单保留。

好友申请也支持部分已完成的正文事件识别，user 的同意与否仍需明确操作或已发生的行动；手机号、联系人关系等遵循原手机功能的存档机制。

## 开发接口与账本约束

**存储位置**：继续保存在单独角色聊天存档的现有 `chatMetadata.st_little_phone_v1` 结构中，向后兼容旧存档。新增可选字段：
- `wallet.balanceCents`：用户账户余额（整数分）。
- `wallet.ledger[]`：具有唯一 ID 的入账、扣款、退款、调整和未来订单条目。
- `wallet.transfers[]`：转账/红包，包含来源、方向、金额、状态、联系人和正文来源指纹。
- `wallet.events[]`：账本局部事件，保留最近 300 条。
- `storyEvents[]`：跨应用事件记录，保留最近 400 条。

**操作约束**：
- `walletCents`：解析元为分，不使用浮点数进行累计。
- `walletApplyEntry(data,{id,amountCents,...})`：唯一 ID 入账；余额不足拒绝负数账单。
- `walletCreateTransfer(data,{id,kind,from,contactId,amountCents})`：建立带状态的交易；user 发出时立即预留/扣款，角色发来时不自动增加 user 余额。
- `walletSettleTransfer(data,id,status)`：只允许待处理转入收款、拒收、撤回或到期，重复调用不会二次入账。
- `walletChargeOrder(data,{orderId,amountCents,shop,category})`：为未来购物（shopping）、外卖（takeout）、服务（service）扣款，订单唯一 ID 去重；订单金额必须为正，余额不足不能付款。
- `walletRefundOrder(data,{orderId,amountCents,category})`：对应订单退款，不允许超过支付金额；当前按单笔全额/单次退款实现，后续增加部分退款需扩展退款 ID。
- `phonePublishEvent(data, event)` / `publishPhoneAppEvent(data,{app,action,id,detail,...})`：跨应用事实发布与去重，供之后的微博、购物和外卖继续接入。

**正文接口**：SillyTavern 1.18/1.19 的 `eventSource` / `event_types` 监听 MESSAGE_RECEIVED、MESSAGE_SENT、MESSAGE_EDITED、MESSAGE_UPDATED、MESSAGE_DELETED、MESSAGE_SWIPED、GENERATION_ENDED、CHAT_CHANGED；正文可读取 `setExtensionPrompt` 注入的已确认事件。对“正在发生”的不明确事实采用不处理的保守策略。任何一个交易事件最多对应一笔账单，修改或切换回复时重新核对来源指纹。

## 尚未完成或不保证的部分

- 此版本**没有**推出微博、外卖和购物应用界面；这里只预留余额、账单、订单和事件连接。
- 目前不能识别正文中所有隐喻、特殊文风、一次多笔资金混写；优先避免凭空创造事实。
- 当前主要为主角色正文提供自动转账识别；NPC 私聊支持手动转账红包，但 NPC 在正文中的所有资金事件尚未建立通用身份匹配。
- 正文好友关系的复杂重生成冲突还需要进一步增强冲正；不自动撤回 user 已明确同意过的关系。
- 事件同步依赖打开的酒馆环境，不在酒馆关闭时后台运行。
- 本版本已做代码与模拟场景检查，**尚未在用户安卓端及真实模型上完成整体验收**。

## 建议验收步骤

1. 先给吱付宝设定 ¥300。向好友发 ¥99.90 红包，余额应为 ¥200.10；撤回后应恢复 ¥300，不得重复入账。
2. 正文生成「我已经给你转了两百块」，打开手机应出现一张待收款卡片。点击收款后吱付宝增加 ¥200，并在下一轮正文提示中出现收款事实。
3. 将这条正文改成「我打算给你转两百块」，再次核对，旧交易应失效并尝试冲正。
4. 将正文切回原回复，应该出现**新的**待收款，而不是沿用旧已冲正交易。
5. 用手机日历或聊天的跳转时间快进 24 小时，未领取的交易应过期并退还余额。
6. 切换其他角色聊天存档、再返回，余额账本应保持各自独立；购物/外卖完整流程后续上线再测试。
